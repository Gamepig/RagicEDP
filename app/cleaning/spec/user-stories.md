## US1: 基礎清洗功能 [P1]

### 故事描述

```
作為 系統管理員
我希望 系統能自動執行 SQL 規則清洗
以便 快速處理可自動修正的資料問題
```

### 驗收條件

- [ ] AC1.1: 系統能從 BigQuery 提取當日新增資料
- [ ] AC1.2: 系統能載入並解析 YAML 規則配置
- [ ] AC1.3: 系統能執行 144 條基礎規則檢查
- [ ] AC1.4: 系統能自動修正可修正的問題
- [ ] AC1.5: 系統能記錄所有違規與修正歷史
- [ ] AC1.6: 系統能更新 cleaning_status 欄位

### 規則分類

| 類別 | 規則數 | 說明 |
|------|--------|------|
| FMT-* | 9 | 格式驗證 |
| FK-* | 5 | 外鍵參照 |
| NUM-* | 15 | 數值範圍 |
| UNQ-* | 4 | 唯一性 |
| REQ-* | 28 | 必填欄位 |
| TMP-* | 8 | 時間邏輯 |
| ASC-* | 35 | 關聯規則 |
| MKT-* | 40 | 行銷規則 |

### 技術規格

```python
# 主要元件
- RuleRegistry: 規則註冊表
- SQLCleaner: SQL 檢查器
- FieldFixer: 欄位修正器
- ResultWriter: 結果寫入器
- CleaningEngine: 清洗引擎
```

## US2: 自動補足功能 [P2]

### 故事描述

```
作為 系統管理員
我希望 系統能自動補足缺失欄位
以便 減少人工填寫的工作量
```

### 驗收條件

- [ ] AC2.1: 系統能從關聯表補足缺失欄位
- [ ] AC2.2: 系統能計算客戶統計欄位
- [ ] AC2.3: 系統能計算衍生欄位（RFM、沉睡狀態等）
- [ ] AC2.4: 系統能自動建立促銷活動記錄
- [ ] AC2.5: 補足結果記錄到歷史表

### 規則分類

| 類別 | 規則數 | 說明 |
|------|--------|------|
| FILL-OD-* | 6 | 訂單關聯補足 |
| FILL-CUST-* | 7 | 客戶統計計算 |
| FILL-DERIVED-* | 7 | 衍生欄位計算 |
| ACT-* | 4 | 活動自動補建 |

### 技術規格

```python
# 主要元件
- AutoFiller: 自動補足執行器
- DerivedCalculator: 衍生欄位計算器
```

### 補足規則範例

```yaml
# FILL-OD-001: 從訂單明細補足客戶編號
- id: FILL-OD-001
  name: 補足訂單客戶編號
  source_table: sheet_99_order_detail
  target_table: sheet_50_order
  source_field: 客戶編號
  target_field: customer_code
  join_key: order_no
```

## US3: AI 判斷功能 [P3]

### 故事描述

```
作為 系統管理員
我希望 系統能使用 AI 分析複雜問題
以便 提高自動修正的覆蓋率
```

### 驗收條件

- [ ] AC3.1: 系統能呼叫 OpenRouter API
- [ ] AC3.2: 系統能建構有效的分析 Prompt
- [ ] AC3.3: AI 信心度 > 0.9 時自動修正
- [ ] AC3.4: AI 信心度 < 0.9 時標記待人工處理
- [ ] AC3.5: AI 分析結果記錄到歷史表

### AI 模型配置

| 模型 | 用途 | 優先級 |
|------|------|--------|
| claude-3-5-sonnet | 主要分析 | 1 |
| gemini-2.0-flash | 備用/快速 | 2 |

### 技術規格

```python
# 主要元件
- OpenRouterClient: API 客戶端
- AIAnalyzer: AI 分析器
- PromptBuilder: Prompt 建構器

# 信心度閾值
CONFIDENCE_THRESHOLD = 0.9
```

## US4: 通知功能 [P4]

### 故事描述

```
作為 系統管理員
我希望 收到清洗結果通知
以便 及時處理需人工處理的資料
```

### 驗收條件

- [ ] AC4.1: 系統能發送 Email 通知
- [ ] AC4.2: 系統能發送 LINE 通知
- [ ] AC4.3: 通知包含統計摘要
- [ ] AC4.4: 通知包含問題資料連結
- [ ] AC4.5: 只在有待處理項目時發送

### 通知內容

```
標題: [RagicEDP] 資料清洗通知 - 2026-01-11

統計摘要:
- 總處理筆數: 1,234
- 自動修正: 1,100
- AI 修正: 80
- 需人工處理: 54

待處理項目:
[查看詳情] -> 資料修正介面連結
```

### 技術規格

```python
# 主要元件
- CleaningNotifier: 通知調度器
- EmailSender: Email 發送器
- LineSender: LINE 發送器
```

## US5: 資料修正介面 [P5]

### 故事描述

```
作為 操作人員
我希望 有 Web 介面可以修正資料
以便 方便地處理需人工處理的項目
```

### 驗收條件

- [ ] AC5.1: 可查看待處理資料清單
- [ ] AC5.2: 可篩選表格、日期、狀態
- [ ] AC5.3: 可查看單筆資料詳情
- [ ] AC5.4: 可手動修正欄位值
- [ ] AC5.5: 可呼叫 AI 獲取建議
- [ ] AC5.6: 修正後更新 cleaning_status
- [ ] AC5.7: 修正歷史可追溯

### 頁面設計

```
1. 首頁 (Dashboard)
   - 統計圖表
   - 待處理數量
   - 快速入口

2. 資料清單頁
   - 篩選器（表格、日期、狀態）
   - 資料表格
   - 分頁

3. 資料詳情頁
   - 原始值 vs 清洗值
   - 違規項目
   - AI 建議
   - 修正表單
```

### 技術規格

```
Backend:
- FastAPI
- SQLAlchemy (BigQuery)
- Pydantic

Frontend:
- React 18
- Ant Design 5
- React Query
```
