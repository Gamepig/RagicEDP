## 一、專案概述

### 1.1 專案目標

RagicEDP（Ragic Extract, Data cleansing, Presentation）是一套**自動化資料管理系統**，目標：

1. **自動化資料備份**：每日增量從 Ragic 同步至 BigQuery
2. **自動化資料清洗**：AI + SQL 雙層清洗，持續維護資料品質
3. **智能資料分析**：支援行銷分析、客戶分群、銷售預測

### 1.2 核心特性

| 特性 | 說明 |
|------|------|
| **非一次性** | 持續運行的自動化系統，非一次性清洗 |
| **增量處理** | 每日增量備份與清洗，降低資源消耗 |
| **規則演進** | 清洗規則可迭代擴展，支援自主學習 |
| **可追溯** | 保留原始資料，支援清洗結果審計 |

## 三、技術架構決策

### 3.1 技術棧

| 層級 | 技術選型 | 說明 |
|------|---------|------|
| 資料來源 | Ragic REST API | 每頁 1000 筆，分頁抓取 |
| 資料倉庫 | BigQuery | asia-east1，專案 b25h01-ragic |
| 運算平台 | Cloud Functions | Python 3.11，512Mi 記憶體 |
| 排程 | Cloud Scheduler | 每日增量 + 每週報告 |
| 通知 | SMTP Email | 週報告發送 |

### 3.2 資料流程

```
┌─────────────────────────────────────────────────────────────┐
│                    每日備份流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Ragic API ──增量抓取──▶ 初步過濾 ──▶ BQ 原始表            │
│       ↓               (BACKUP-FILTER)      ↓                │
│  Cloud Scheduler                      定期觸發               │
│  (每日 03:00)                              ↓                │
│                                       BQ 清洗表              │
│                                      (完整清洗)              │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 週報告流程（每週日 00:00）                           │   │
│  ├─────────────────────────────────────────────────────┤   │
│  │ [BigQuery] ──統計分析──▶ [報告生成] ──▶ [Email]     │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 清洗執行策略

| 階段 | 執行時機 | 規則類型 | 說明 |
|------|---------|---------|------|
| **初步過濾** | 寫入 BQ **前** | BACKUP-FILTER A/B/C | 過濾無分析價值的垃圾記錄 |
| **完整清洗** | 寫入 BQ **後** | FMT/FK/NUM/ASSOC/MKT... | 定期排程或增量觸發，保留原始資料 |

**理由**：
1. 初步過濾規則穩定且簡單，可在備份時執行
2. 完整清洗規則需迭代演進，寫入後執行可保留原始資料供追溯

## 六、關鍵發現與決策

### 6.1 資料品質發現

1. **品牌參照問題**（原 45%）：透過品牌清洗解決，而非補充品牌表
2. **未來日期異常**（47 筆）：2058-2059 年的記錄，已由 BACKUP-FILTER-C 過濾
3. **客戶生日全空**（100%）：待確認是否需要此欄位
4. **活動參照缺失**（14,133 筆）：待確認活動表是否完整

### 6.2 架構決策

| 決策項目 | 決定 | 理由 |
|---------|------|------|
| 清洗時機 | 混合策略 | 初步過濾寫入前，完整清洗寫入後 |
| 原始資料保留 | 是 | 支援追溯與規則迭代 |
| 規則儲存格式 | JSON | 便於程式讀取與擴展 |
| 增量基準時間 | 昨天 00:00 | 固定時間，移除 BQ 查詢依賴 |

### 6.3 Ragic API 發現

1. **無 count 端點**：無法預知資料量
2. **分頁參數**：使用 `offset` 而非 `qs`
3. **Listing 模式不完整**：不適用於增量備份
4. **每日增量**：通常 < 1000 筆，效能已足夠
