## 一、專案概述

### 1.1 專案目標

RagicEDP（Ragic Extract, Data cleansing, Presentation）是一套**自動化資料管理系統**：

| 目標 | 說明 | 狀態 |
|------|------|------|
| 自動化資料備份 | 每日增量從 Ragic 同步至 BigQuery | ✅ 已實作 |
| 自動化資料清洗 | AI + SQL 雙層清洗，持續維護資料品質 | ⏳ 部分完成 |
| 智能資料分析 | 支援行銷分析、客戶分群、銷售預測 | ⏳ 待開發 |
| 資料修正介面 | Web 介面瀏覽與修正 BigQuery 資料 | ⏳ 待開發 |

### 1.2 技術架構

| 層級 | 技術選型 | 說明 |
|------|---------|------|
| 資料來源 | Ragic REST API | 每頁 1000 筆，分頁抓取 |
| 資料倉庫 | BigQuery | asia-east1，專案 b25h01-ragic |
| 備份系統 | Cloud Functions | Python 3.11，512Mi 記憶體 |
| 排程 | Cloud Scheduler | 每日增量 + 每週報告 |
| 資料修正介面 | Cloud Run | React + FastAPI |
| 通知 | SMTP Email | 週報告/失敗通知 |

## 三、增量備份系統 v3 ✅ 已完成

### 3.1 設計原則

| 原則 | 說明 |
|------|------|
| 固定時間基準 | 使用「昨天 00:00」作為基準時間，不從 BQ 查詢 |
| 移除 BQ 查詢依賴 | 時間基準固定計算，不需讀取 backup_status |
| 單一模組設計 | 核心邏輯集中在 incremental.py |

### 3.2 五步驟流程

```
Step 1: 計算備份基準時間
  → backup_base_time = yesterday 00:00 (Asia/Taipei)

Step 2: 從 Ragic 抓取新資料
  → 使用 where 過濾 >= base_time 的資料
  → 不設 limit，返回所有符合條件的資料
  → 使用 offset 分頁（正確的分頁參數）

Step 3: 初步清洗 (BACKUP-FILTER)
  → 規則 A：99 表嚴格模式（關鍵欄位全空→跳過）
  → 規則 B：其他表寬鬆模式（主鍵空→跳過）
  → 規則 C：過濾未來日期（> 今天→跳過）

Step 4: 分區資料
  → 查詢 BQ 現有 ragic_id
  → 區分新增/更新資料

Step 5: 上傳到 BQ
  → 新資料 → Streaming Insert
  → 更新資料 → DML UPDATE
  → 記錄結果到 backup_logs
```

## 七、系統運營規則

### 7.1 備份系統分工

| 程式 | 用途 | 觸發方式 |
|------|------|---------|
| `incremental.py` | 每日增量備份 | Cloud Scheduler 自動執行 |
| `manual_backup.py` | 手動補抓資料 | 手動執行，可指定日期 |
| `full_backup.py` | 全量備份 | 手動執行，重建所有資料 |

### 7.2 常用命令

```bash
# 每日自動增量備份（Cloud Scheduler 觸發）
uv run python -m src.main

# 手動補抓特定日期的資料
uv run python src/manual_backup.py --from-date 2026-01-05

# 手動補抓並上傳至 BigQuery
uv run python src/manual_backup.py --from-date 2026-01-05 --to-bq

# 全量備份（重建所有資料）
uv run python src/full_backup.py

# 本地測試
uv run pytest -v
```

### 7.3 備份失敗處理

| 情況 | 處理方式 |
|------|---------|
| 單日失敗 | 隔天自動補回（會抓取前一天的資料）|
| 連續多日失敗 | 使用 manual_backup.py 指定日期補抓 |
| 資料損壞 | 執行 full_backup.py 全量重建 |
