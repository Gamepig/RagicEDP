# 資料修正介面規劃

> **版本**: v1.0
> **建立日期**: 2025-01-01
> **狀態**: 規劃中
> **決策**: 採用 Cloud Run 架構

---

## 一、專案目標

建立一個 Web 介面，讓使用者可以：
1. 瀏覽 BigQuery 中的資料
2. 修正有問題的資料
3. 透過 AI 輔助識別與建議修正

---

## 二、技術決策

### 2.1 架構選型比較

| 方案 | 優點 | 缺點 | 結論 |
|------|------|------|------|
| Cloud Functions + Firebase Hosting | 分離部署、成本低 | 前後端分離複雜、Functions 有超時限制 | ❌ 不採用 |
| **Cloud Run** | 全端整合、支援長時間運算、內建認證 | 需要容器化 | ✅ **採用** |
| App Engine | 完整支援 | 較舊、彈性較差 | ❌ 不採用 |

### 2.2 選擇 Cloud Run 的原因

1. **前後端整合**: 可同時運行 React SPA 與 Python 後端
2. **GCP 整合**: 內建服務帳戶，無需額外設定即可連接 BigQuery
3. **AI 支援**: 支援 Vertex AI 長時間呼叫（最長 60 分鐘）
4. **即時功能**: 支援 WebSocket（未來可做即時協作）
5. **部署簡單**: 前後端打包同一容器，一次部署

## 七、API 設計

### 7.1 資料操作

```
GET  /api/tables                    # 取得所有資料表
GET  /api/tables/{table}/records    # 取得記錄（分頁）
GET  /api/tables/{table}/schema     # 取得欄位定義
PUT  /api/records/{id}              # 更新單筆記錄
POST /api/records/batch             # 批次更新
```

### 7.2 修正功能

```
GET  /api/corrections               # 取得修正歷史
POST /api/corrections               # 建立修正記錄
GET  /api/corrections/{id}/diff     # 查看變更差異
```

### 7.3 AI 功能

```
POST /api/ai/detect                 # AI 偵測異常
POST /api/ai/suggest                # AI 建議修正
POST /api/ai/explain                # AI 說明問題
```

## 九、部署配置

### 9.1 Cloud Run 設定

```yaml
# cloudbuild.yaml
steps:
  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'gcr.io/$PROJECT_ID/data-correction-app', '.']
  - name: 'gcr.io/cloud-builders/docker'
    args: ['push', 'gcr.io/$PROJECT_ID/data-correction-app']
  - name: 'gcr.io/google.com/cloudsdktool/cloud-sdk'
    args:
      - 'run'
      - 'deploy'
      - 'data-correction-app'
      - '--image=gcr.io/$PROJECT_ID/data-correction-app'
      - '--region=asia-east1'
      - '--platform=managed'
      - '--allow-unauthenticated'
```

### 9.2 環境變數

```bash
PROJECT_ID=b25h01-ragic
BQ_DATASET=erp_backup
VERTEX_AI_LOCATION=asia-east1
```
