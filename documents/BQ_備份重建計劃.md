## 執行計劃

### Phase 1: 舊資料整合

**目標**: 整合分片資料，產出各表格完整 JSON

```
任務:
1.1 整合表 50 訂單表（14 分片 → 1 檔案）
1.2 整合表 99 訂單明細表（61 分片 → 1 檔案）
1.3 驗證各表記錄數
1.4 產出整合報告

輸出路徑: test_workspace/consolidated/
```

### Phase 2: BQ 清理

**目標**: 刪除所有舊表格，清空 dataset

```
任務:
2.1 刪除所有 __tmp_merge_* 臨時表
2.2 刪除 ragic_data, ragic_data_staging
2.3 刪除 ragic_data_backup_* 備份表
2.4 確認 run_results 是否保留
2.5 驗證 dataset 已清空

注意: 此操作不可逆，需確認後執行
```

### Phase 3: 建立新表格結構

**目標**: 為每個 Ragic 表單建立獨立 BQ 表

```
新表格命名規則: ragic_{表格代號}_{表格名稱}

| BQ 表格名稱 | 對應 Ragic |
|-------------|-----------|
| ragic_10_品牌表 | forms8/5 |
| ragic_20_通路表 | forms8/4 |
| ragic_30_金流表 | forms8/7 |
| ragic_40_物流表 | forms8/1 |
| ragic_41_郵遞區號表 | forms8/6 |
| ragic_50_訂單表 | forms8/17 |
| ragic_60_客戶表 | forms8/2 |
| ragic_70_商品表 | forms8/9 |
| ragic_80_活動管理表 | forms8/10 |
| ragic_99_訂單明細表 | forms8/3 |

Schema 策略: 使用自動偵測（autodetect）
```

### Phase 4: 上傳初始資料

**目標**: 將整合後的舊資料上傳到各 BQ 表

```
任務:
4.1 上傳各表初始資料（使用 bq load）
4.2 驗證每表記錄數
4.3 上傳增量測試資料
4.4 產出上傳報告
```

### Phase 5: 建立正式增量備份系統

**目標**: 基於測試程式建立正式版本

```
任務:
5.1 整合 test_incremental_fetch_v2.py 到正式版本
5.2 新增 BQ 上傳功能
5.3 新增執行日誌記錄
5.4 設計 GCS 觸發機制
5.5 建立監控與告警

正式程式路徑: scripts/ragic_backup.py
```

| 風險 | 影響 | 對策 |
