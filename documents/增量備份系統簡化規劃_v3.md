# Ragic 增量備份系統簡化規劃 v3

**版本**: v3.0
**建立日期**: 2025-12-30
**狀態**: ✅ 已確認

---

## 1. 現有系統複雜度分析

### 1.1 當前架構問題

| 問題 | 說明 | 影響 |
|------|------|------|
| **時間取得邏輯複雜** | 需查詢 BQ backup_status 表取得 last_record_time | 額外的 BQ 查詢開銷 |
| **時間緩衝機制** | TIME_BUFFER_SECONDS = 60 往前推 60 秒 | 邏輯複雜，可能抓到重複資料 |
| **多重時間格式解析** | 支援 3 種日期格式 + 時間戳格式 | 程式碼冗長，容易出錯 |
| **狀態表維護** | 需維護 backup_status + backup_logs 兩個管理表 | 維護成本高 |
| **並行分頁邏輯** | 資料量大時使用並行抓取 | 增加複雜度，日常使用率低 |

### 1.2 實際使用場景

根據過去的運行記錄：
- **每日增量資料量**：通常 < 1,000 筆
- **執行時間**：< 2 秒
- **並行分頁使用率**：幾乎不會觸發（資料量不足 5,000 筆）

**結論**：現有系統過度設計，需要大幅簡化。

## 2. 簡化設計原則

### 2.1 核心簡化思路

| 原則 | 說明 |
|------|------|
| **固定時間基準** | 備份固定每日 00:00 執行，使用「昨天 00:00」作為基準時間 |
| **移除 BQ 查詢依賴** | 不再從 BQ 讀取最後備份時間，改用固定時間計算 |
| **簡化重試機制** | 使用 Fallback 策略處理備份失敗的情況 |
| **單一模組設計** | 合併為更少的模組，降低維護成本 |

### 2.2 時間基準計算

```
┌─────────────────────────────────────────────────────────────┐
│ 每日 00:00 執行備份                                          │
│                                                              │
│   備份基準時間 = 當天 00:00 - 24 小時 = 昨天 00:00             │
│                                                              │
│   例：2025-12-30 00:00 執行                                  │
│        → 抓取 >= 2025-12-29 00:00 修改的資料                  │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 Fallback 策略（處理備份失敗）

```
如果昨天備份失敗：
  1. 系統仍使用「昨天 00:00」作為基準
  2. 會自動補回昨天遺漏的資料
  3. 不需要額外的 BQ 查詢

如果連續多天失敗：
  1. 可手動執行全量備份
  2. 或手動指定起始時間
```

### 3.2 各步驟詳細說明

#### Step 1: 計算備份基準時間

```python
from datetime import datetime, timedelta

def get_backup_base_time() -> datetime:
    """
    計算備份基準時間

    固定邏輯：今天 00:00 - 24 小時 = 昨天 00:00
    """
    today = datetime.now().replace(hour=0, minute=0, second=0, microsecond=0)
    return today - timedelta(days=1)
```

**說明**：
- 每日 00:00 執行時，`today` = 當天 00:00
- `backup_base_time` = 昨天 00:00
- 抓取所有 `最後修改日期 >= 昨天 00:00` 的資料

#### Step 2: 從 Ragic 抓取新資料

```python
def fetch_incremental_data(sheet_code: str, base_time: datetime) -> List[Dict]:
    """
    從 Ragic 抓取增量資料

    注意：不設置 limit 參數，讓 Ragic API 返回所有符合條件的資料
    """
    config = SHEET_CONFIG[sheet_code]

    # 格式化時間
    time_str = base_time.strftime('%Y/%m/%d %H:%M:%S')

    # 建構 API URL（不設置 limit，抓取所有符合條件的資料）
    url = f"{BASE_URL}/{config['ragic_path']}"
    params = {
        'api': '',
        'v': 3,
        'where': f"{config['last_modified_field_id']},gt,{time_str}"
    }

    # 發送請求
    response = requests.get(url, params=params, headers=headers)
    records = parse_response(response.json())

    return records
```

**注意**：
- 不設置 `limit` 參數，讓 API 返回所有符合條件的資料
- 不再使用 `status_field` 過濾（移除 API 層過濾）
- 狀態過濾改為在 Step 3 清洗階段處理

#### Step 3: 初步清洗

```python
def filter_records(records: List[Dict], sheet_code: str) -> Tuple[List[Dict], int]:
    """
    初步清洗資料

    規則 A (99 表)：訂單編號 + 商品編號 都為空 → 跳過
    規則 B (其他表)：主鍵為空 → 跳過
    規則 C (全部)：最後修改日期為未來 → 跳過
    """
    config = SHEET_CONFIG[sheet_code]
    now = datetime.now()

    valid = []
    filtered = 0

    for record in records:
        # 規則 C: 過濾未來日期
        if is_future_date(record, config, now):
            filtered += 1
            continue

        # 規則 A/B: 驗證關鍵欄位
        if sheet_code == '99':
            if not validate_strict(record, config):
                filtered += 1
                continue
        else:
            if not validate_loose(record, config):
                filtered += 1
                continue

        valid.append(record)

    return valid, filtered
```

#### Step 4: 分區資料

```python
def partition_records(
    records: List[Dict],
    sheet_code: str
) -> Tuple[List[Dict], List[Dict]]:
    """
    分區資料：區分新增和更新
    """
    config = SHEET_CONFIG[sheet_code]
    table_name = config['bq_table']

    # 取得現有的 ragic_id
    existing_ids = get_existing_ids(table_name)

    # 分區
    to_insert = []
    to_update = []

    for record in records:
        ragic_id = record.get('_ragicId', '')
        if ragic_id in existing_ids:
            to_update.append(record)
        else:
            to_insert.append(record)

    return to_insert, to_update
```

#### Step 5: 上傳到 BQ

```python
def upload_to_bq(
    to_insert: List[Dict],
    to_update: List[Dict],
    sheet_code: str
) -> Tuple[int, int]:
    """
    上傳資料到 BigQuery
    """
    config = SHEET_CONFIG[sheet_code]
    table_name = config['bq_table']

    inserted = 0
    updated = 0

    # 新增資料
    if to_insert:
        rows = [prepare_row(r, config) for r in to_insert]
        insert_rows(table_name, rows)
        inserted = len(to_insert)

    # 更新資料
    if to_update:
        for record in to_update:
            row = prepare_row(record, config)
            update_row(table_name, row)
            updated += 1

    return inserted, updated
```

## 4. 清洗規則定義

### 4.1 規則總覽

| 規則 | 適用表格 | 模式 | 判斷邏輯 |
|------|---------|------|---------|
| 規則 A | 99 訂單明細 | 嚴格 | 訂單編號 + 商品編號 都為空 → 跳過 |
| 規則 B | 其他所有表 | 寬鬆 | 主鍵欄位為空 → 跳過 |
| 規則 C | 全部表格 | 時間 | 最後修改日期 > 今天 → 跳過 |

### 4.2 規則 A：99 表嚴格模式

```python
def validate_strict(record: Dict, config: Dict) -> bool:
    """
    99 表嚴格驗證

    邏輯：訂單編號 + 商品編號 至少有一個有值
    """
    order_code = get_field_value(record, '訂單編號', '1000781')
    product_code = get_field_value(record, '商品編號', '1000811')

    # 兩者都為空才跳過
    return bool(order_code) or bool(product_code)
```

### 4.3 規則 B：寬鬆模式

```python
PRIMARY_KEYS = {
    '10': ('品牌編號', '1000942'),
    '20': ('通路編號', '1000921'),
    '30': ('金流編號', '1000954'),
    '40': ('物流編號', '1000736'),
    '41': ('郵遞區號', '1000964'),
    '50': ('訂單編號', '1000976'),
    '60': ('客戶編號', '1000710'),
    '70': ('商品編號', '1000998'),
    '80': ('活動編號', '1001019'),
}

def validate_loose(record: Dict, config: Dict) -> bool:
    """
    寬鬆驗證：主鍵不為空
    """
    pk_name, pk_id = PRIMARY_KEYS.get(config['sheet_code'], (None, None))
    if not pk_name:
        return True

    value = get_field_value(record, pk_name, pk_id)
    return bool(value)
```

### 4.4 規則 C：未來日期過濾

```python
def is_future_date(record: Dict, config: Dict, now: datetime) -> bool:
    """
    檢查是否為未來日期

    目的：過濾 2058-2059 年等異常資料
    """
    modified_str = record.get(config['last_modified_field'], '')
    if not modified_str:
        return False

    try:
        modified_time = parse_datetime(modified_str)
        return modified_time > now
    except:
        return False
```

### 5.3 incremental.py 設計

```python
"""
Ragic 增量備份核心模組 v3
"""
from datetime import datetime, timedelta
from typing import Dict, List, Tuple, Any
from google.cloud import bigquery
import requests

from .config import RAGIC_CONFIG, SHEET_CONFIG, BIGQUERY_CONFIG


class IncrementalBackup:
    """增量備份執行器"""

    def __init__(self):
        self.bq_client = bigquery.Client(project=BIGQUERY_CONFIG['project_id'])

    def run(self, sheet_codes: List[str] = None) -> Dict[str, Any]:
        """
        執行增量備份

        Args:
            sheet_codes: 要備份的表格代碼（None = 全部）

        Returns:
            備份結果摘要
        """
        if sheet_codes is None:
            sheet_codes = list(SHEET_CONFIG.keys())

        # Step 1: 計算備份基準時間
        base_time = self._get_backup_base_time()

        results = {
            'backup_time': datetime.now().isoformat(),
            'base_time': base_time.isoformat(),
            'sheets': {},
        }

        for sheet_code in sheet_codes:
            result = self._backup_sheet(sheet_code, base_time)
            results['sheets'][sheet_code] = result

        return results

    def _get_backup_base_time(self) -> datetime:
        """計算備份基準時間：昨天 00:00"""
        today = datetime.now().replace(hour=0, minute=0, second=0, microsecond=0)
        return today - timedelta(days=1)

    def _backup_sheet(self, sheet_code: str, base_time: datetime) -> Dict[str, Any]:
        """備份單一表格"""
        try:
            # Step 2: 抓取資料
            records = self._fetch_data(sheet_code, base_time)

            if not records:
                return {'status': 'skipped', 'message': 'No new data'}

            # Step 3: 初步清洗
            valid_records, filtered_count = self._filter_records(records, sheet_code)

            # Step 4: 分區
            to_insert, to_update = self._partition_records(valid_records, sheet_code)

            # Step 5: 上傳
            inserted, updated = self._upload_records(to_insert, to_update, sheet_code)

            return {
                'status': 'success',
                'fetched': len(records),
                'filtered': filtered_count,
                'inserted': inserted,
                'updated': updated,
            }

        except Exception as e:
            return {'status': 'failed', 'error': str(e)}

    # ... 其他方法實作 ...
```

## 9. 風險評估

### 9.1 潛在風險

| 風險 | 說明 | 緩解措施 |
|------|------|---------|
| **備份失敗未補回** | 如果連續多天失敗，可能遺漏資料 | 另外寫一組手動全量備份模組 |
| **時區問題** | 如果系統時區不是 Asia/Taipei | 使用 pytz 明確指定時區 |
| **資料量突增** | 某天資料量超過預期 | 不設 limit，讓 API 返回所有資料 |

### 9.2 配套措施

1. **另外開發全量備份模組**：獨立的手動全量備份程式，用於初始化或緊急恢復
2. **記錄詳細日誌**：便於問題排查，寫入 backup_logs 表
3. **Email 失敗通知**：備份失敗時發送通知信

## 12. 系統運營規則

### 12.1 備份系統分工

| 程式 | 用途 | 時間基準 | 觸發方式 |
|------|------|---------|---------|
| `incremental.py` | 每日增量備份 | 固定：昨天 00:00 | Cloud Scheduler 自動執行 |
| `manual_backup.py` | 手動補抓資料 | 可指定任意日期 | 手動執行 |
| `full_backup.py` | 全量備份 | 無時間過濾 | 手動執行 |
| 資料修正介面 | 資料修正/更新 | - | 另案開發 |

### 12.2 運營規則

```
┌─────────────────────────────────────────────────────────────┐
│                     系統運營規則                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  規則 1：增量備份時間基準固定                                  │
│  ┌─────────────────────────────────────────────┐            │
│  │  incremental.py 每日 00:00 執行              │            │
│  │  固定抓取「昨天 00:00 之後」修改的資料         │            │
│  │  → 不從 BQ 或本地檔案讀取最後備份時間          │            │
│  │  → 不允許修改時間基準計算邏輯                  │            │
│  └─────────────────────────────────────────────┘            │
│                                                              │
│  規則 2：資料修正另案開發                                      │
│  ┌─────────────────────────────────────────────┐            │
│  │  資料修正/更新功能：                          │            │
│  │  → 與「資料修正介面」一起開發                  │            │
│  │  → 不使用備份程式進行資料修正                  │            │
│  │  → 不修改 incremental.py 的邏輯              │            │
│  └─────────────────────────────────────────────┘            │
│                                                              │
│  規則 3：備份失敗處理                                          │
│  ┌─────────────────────────────────────────────┐            │
│  │  單日失敗：                                   │            │
│  │  → 隔天自動補回（因為會抓取前一天的資料）      │            │

```

### 12.3 程式使用範例

```bash
# 每日自動增量備份（Cloud Scheduler 觸發）
# 固定抓取昨天 00:00 之後的資料
uv run python -m src.main

# 手動補抓特定日期的資料（輸出至本地 JSON）
uv run python src/manual_backup.py --from-date 2026-01-05

# 手動補抓並上傳至 BigQuery
uv run python src/manual_backup.py --from-date 2026-01-05 --to-bq

# 全量備份（重建所有資料）
uv run python src/full_backup.py

# 資料修正 → 使用資料修正介面（另案開發）
```
