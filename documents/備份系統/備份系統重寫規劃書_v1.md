## 2. 技術研究結果

### 2.1 Ragic API 增量抓取能力

**結論**: Ragic API 完全支援增量抓取

| 功能 | 支援 | 說明 |
|------|------|------|
| 日期篩選 | ✅ | 使用 `where` 參數 |
| 大於比較 | ✅ | `gt` (大於), `gte` (大於等於) |
| 分頁抓取 | ✅ | `limit` + `offset` |
| 排序 | ✅ | `order` 參數 |

**API 語法範例**:
```bash
# 抓取 2025/12/25 14:30:00 之後修改的資料
?where=1000834,gt,2025/12/25 14:30:00&order=1000834,ASC&limit=1000
```

## 3. 架構設計

### 3.1 系統流程圖

```
┌─────────────────────────────────────────────────────────────────────┐
│                     每日備份流程 (00:00)                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  Step 1: 讀取備份狀態表                                               │
│  ┌─────────────────────────────────────────────┐                    │
│  │  SELECT sheet_code, last_backup_time        │                    │
│  │  FROM backup_status                         │                    │
│  └─────────────────────────────────────────────┘                    │
│                         ↓                                            │
│  Step 2: 迴圈處理每個表單                                             │
│  ┌─────────────────────────────────────────────┐                    │
│  │  FOR each sheet_code:                       │                    │
│  │    IF last_backup_time IS NULL:             │                    │
│  │      → 首次備份，抓取全部                    │                    │
│  │    ELSE:                                    │                    │
│  │      → 增量抓取 (where > last_backup_time)  │                    │
│  └─────────────────────────────────────────────┘                    │
│                         ↓                                            │
│  Step 3: 資料過濾 (可選)                                              │
│  ┌─────────────────────────────────────────────┐                    │
│  │  - 排除無效記錄（見 3.3 節）                 │                    │
│  └─────────────────────────────────────────────┘                    │
│                         ↓                                            │
│  Step 4: 上傳至 BigQuery                                             │
│  ┌─────────────────────────────────────────────┐                    │
│  │  MERGE INTO ragic_data                      │                    │
│  │  (Upsert by ragic_id + sheet_code)          │                    │
│  └─────────────────────────────────────────────┘                    │
│                         ↓                                            │
│  Step 5: 更新備份狀態表                                               │
│  ┌─────────────────────────────────────────────┐                    │
│  │  UPDATE backup_status                       │                    │
│  │  SET last_backup_time = NOW(),              │                    │
│  │      records_added = N                      │                    │
│  └─────────────────────────────────────────────┘                    │
│                         ↓                                            │
│  Step 6: 寫入備份日誌                                                 │
│  ┌─────────────────────────────────────────────┐                    │
│  │  INSERT INTO backup_logs                    │                    │
│  │  (timestamp, sheet_code, records, status)   │                    │
│  └─────────────────────────────────────────────┘                    │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 BigQuery 表設計

#### 3.2.1 備份狀態表 (backup_status)

用途：記錄每個表的最後備份時間，供增量判斷使用

```sql
CREATE TABLE IF NOT EXISTS `erp_backup.backup_status` (
  sheet_code       STRING NOT NULL,     -- 表格代碼 (10, 20, 99...)
  sheet_name       STRING,              -- 表格名稱
  last_backup_time TIMESTAMP,           -- 最後備份時間
  last_record_time TIMESTAMP,           -- 最後一筆資料的修改時間
  total_records    INT64,               -- 該表總資料量
  status           STRING,              -- 狀態 (active/inactive)
  updated_at       TIMESTAMP            -- 記錄更新時間
);
```

#### 3.2.2 備份日誌表 (backup_logs)

用途：記錄每次備份的詳細資訊，供週報使用

```sql
CREATE TABLE IF NOT EXISTS `erp_backup.backup_logs` (
  id               STRING NOT NULL,     -- UUID
  backup_date      DATE,                -- 備份日期
  backup_time      TIMESTAMP,           -- 備份時間
  sheet_code       STRING NOT NULL,     -- 表格代碼
  sheet_name       STRING,              -- 表格名稱
  records_fetched  INT64,               -- 抓取筆數
  records_inserted INT64,               -- 新增筆數
  records_updated  INT64,               -- 更新筆數
  records_skipped  INT64,               -- 跳過筆數（過濾）
  status           STRING,              -- 狀態 (success/failed/skipped)
  error_message    STRING,              -- 錯誤訊息（如有）
  duration_seconds FLOAT64,             -- 執行時間
  created_at       TIMESTAMP            -- 記錄建立時間
);
```

### 3.3 資料過濾建議

> **待確認**: 以下過濾規則為建議，需與用戶確認

#### 建議過濾條件

| 過濾類型 | 適用表 | 條件 | 說明 |
|---------|--------|------|------|
| **狀態過濾** | 全部 | `使用狀態 = Toggle-Off` | 停用的記錄可能不需備份 |
| **測試資料** | 50, 99 | `訂單編號 LIKE 'TEST%'` | 測試訂單不需備份 |
| **空白記錄** | 全部 | 關鍵欄位為空 | 無意義記錄 |

#### API 層過濾（推薦）

```bash
# 只抓取「使用狀態」為啟用的記錄
# 欄位 ID 需確認，以下為範例
?where=1000946,eq,Toggle-On&where=1000950,gt,2025/12/25
```

**優點**:
- 減少 API 流量
- 減少處理時間
- 減少 BigQuery 儲存成本

**缺點**:
- 無法備份到停用的歷史記錄

#### 程式層過濾

```python
def filter_records(records: list, sheet_code: str) -> list:
    """過濾無用記錄"""
    filtered = []
    for record in records:
        # 跳過停用記錄
        if record.get('使用狀態') == 'Toggle-Off':
            continue
        # 跳過測試訂單
        if sheet_code in ['50', '99']:
            if record.get('訂單編號', '').startswith('TEST'):
                continue
        filtered.append(record)
    return filtered
```
