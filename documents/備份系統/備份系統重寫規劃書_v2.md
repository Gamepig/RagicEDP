```sql
CREATE TABLE IF NOT EXISTS `erp_backup.backup_status` (
  sheet_code        STRING NOT NULL,      -- 表格代碼 (10, 20, 99...)
  sheet_name        STRING,               -- 表格名稱
  bq_table_name     STRING,               -- BQ 表名
  ragic_path        STRING,               -- Ragic API 路徑
  last_backup_time  TIMESTAMP,            -- 最後備份執行時間
  last_record_time  TIMESTAMP,            -- 最後一筆資料的修改時間
  total_records     INT64,                -- 該表總資料量
  last_fetch_count  INT64,                -- 上次抓取筆數
  status            STRING DEFAULT 'active',  -- 狀態
  updated_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP()
);
```

**backup_logs（備份日誌表）**
```sql
CREATE TABLE IF NOT EXISTS `erp_backup.backup_logs` (
  id                STRING NOT NULL,      -- UUID
  backup_date       DATE,                 -- 備份日期
  backup_time       TIMESTAMP,            -- 備份時間
  sheet_code        STRING NOT NULL,      -- 表格代碼
  sheet_name        STRING,               -- 表格名稱
  records_fetched   INT64 DEFAULT 0,      -- 從 API 抓取筆數
  records_inserted  INT64 DEFAULT 0,      -- 新增筆數
  records_updated   INT64 DEFAULT 0,      -- 更新筆數
  records_filtered  INT64 DEFAULT 0,      -- 過濾掉的筆數
  status            STRING,               -- success/failed/skipped
  error_message     STRING,               -- 錯誤訊息
  duration_seconds  FLOAT64,              -- 執行時間
  created_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP()
);
```

```
┌─────────────────────────────────────────────────────────────────────┐
│                     每日備份流程 (00:00 Asia/Taipei)                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  Step 1: 讀取 backup_status 表                                       │
│  ┌─────────────────────────────────────────────┐                    │
│  │  FOR each sheet (10, 20, 30, 40, 41,        │                    │
│  │                  50, 60, 70, 80, 99):       │                    │
│  │    last_time = backup_status[sheet_code]    │                    │
│  └─────────────────────────────────────────────┘                    │
│                         ↓                                            │
│  Step 2: 從 Ragic API 抓取資料（增量 + 過濾）                         │
│  ┌─────────────────────────────────────────────┐                    │
│  │  URL: /forms8/{sheet}?api&v=3               │                    │
│  │       &where={field_id},gt,{last_time}      │  增量條件          │
│  │       &where={status_field},eq,Toggle-On    │  過濾條件          │
│  │       &limit=1000                           │                    │
│  └─────────────────────────────────────────────┘                    │
│                         ↓                                            │
│  Step 3: 資料驗證（檢查關鍵欄位）                                      │
│  ┌─────────────────────────────────────────────┐                    │
│  │  - 跳過關鍵欄位為空的記錄                    │                    │
│  │  - 記錄 filtered 數量                        │                    │
│  └─────────────────────────────────────────────┘                    │
│                         ↓                                            │
│  Step 4: 上傳至對應的 BQ 表                                          │
│  ┌─────────────────────────────────────────────┐                    │
│  │  MERGE INTO sheet_{code}_{name}             │                    │
│  │  USING staging_data                         │                    │
│  │  ON ragic_id = ragic_id                     │                    │
│  │  WHEN MATCHED THEN UPDATE                   │                    │
│  │  WHEN NOT MATCHED THEN INSERT               │                    │

│                         ↓                                            │

│  │  SET last_backup_time = NOW(),              │                    │

│                         ↓                                            │
```

### 3.2 程式層過濾（初步清洗規則）

> **規則編號**: BACKUP-FILTER-001
> **版本**: v1.0
> **建立日期**: 2025-12-30

根據資料清洗規則分析，簡化初步過濾邏輯如下：

#### 規則 A：訂單明細表 (99) - 嚴格模式

**判斷邏輯**：
1. 主鍵為空 → 跳過
2. 關鍵欄位全部為空 → 跳過（只要有一個有值就保留）

| 欄位 | 欄位 ID | 中文名稱 | 說明 |
|------|--------|---------|------|

| 商品編號 | `1000811` | 商品編號 | 商品識別碼，為空則無法分析銷售 |

**判斷公式**：
```
IF (_ragicId IS EMPTY)
THEN SKIP

IF (訂單編號 IS EMPTY) AND (商品編號 IS EMPTY)
THEN SKIP
```

> **備註**：訂單實收欄位不再作為過濾條件，可在後續資料清理階段處理

#### 規則 B：其他表格 (10, 20, 30, 40, 41, 50, 60, 70, 80) - 寬鬆模式

### 3.3 過濾邏輯虛擬碼

```python
def validate_record(record: dict, sheet_code: str) -> bool:
    """
    驗證記錄是否有分析價值

    規則 A (99 訂單明細表): 主鍵為空 或 關鍵欄位全部為空 → 跳過
    規則 B (其他表格): 主鍵為空 → 跳過
    """

    if sheet_code == '99':
        # 規則 A：嚴格模式
        # Step 1: 檢查主鍵
        ragic_id = record.get('_ragicId', '')
        if not ragic_id:
            return False  # 主鍵為空，跳過

        # Step 2: 全部為空才跳過
        critical_fields = ['訂單編號', '商品編號']
        has_any_value = False
        for field in critical_fields:
            value = str(record.get(field, '')).strip()
            if value:
                has_any_value = True
                break
        return has_any_value  # 只要有一個有值就保留

    else:
        # 規則 B：寬鬆模式 - 主鍵為空才跳過
        PRIMARY_KEY = {
            '10': '品牌編號',
            '20': '通路編號',
            '30': '金流編號',
            '40': '物流編號',
            '41': '郵遞區號',
            '50': '訂單編號',
            '60': '客戶編號',
            '70': '商品編號',
            '80': '活動編號',
        }
        pk_field = PRIMARY_KEY.get(sheet_code)
        if pk_field:
            value = str(record.get(pk_field, '')).strip()
            if not value:
                return False  # 主鍵為空，跳過
        return True
```
