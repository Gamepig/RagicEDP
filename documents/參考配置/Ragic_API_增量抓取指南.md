# Ragic API 增量抓取指南

**版本**: v1.0
**建立日期**: 2025-12-25
**用途**: 從 Ragic API 抓取指定時間之後的資料（增量同步）

---

## 1. 核心概念

### 增量抓取原理

增量抓取是指只抓取「上次同步之後有變動的資料」，而非每次都抓取全部資料。這可以：

1. **減少 API 呼叫次數** - 避免重複抓取相同資料
2. **降低網路流量** - 只傳輸有變動的部分
3. **加快同步速度** - 資料量越少處理越快

### 關鍵技術：`where` 參數的日期篩選

Ragic API 支援使用 `where` 參數搭配日期運算符進行篩選：

```
where=欄位ID,運算符,日期值
```

---

## 2. 日期篩選語法

### 日期格式要求

| 格式 | 範例 | 說明 |
|------|------|------|
| `yyyy/MM/dd` | `2025/12/25` | 僅日期 |
| `yyyy/MM/dd HH:mm:ss` | `2025/12/25 14:30:00` | 日期加時間 |

**重要**: 必須使用 `/` 作為分隔符，不支援 `-`

### 支援的運算符

| 運算符 | 說明 | 用途 |
|--------|------|------|
| `gt` | 大於 | 抓取指定時間**之後**的資料 |
| `gte` | 大於等於 | 抓取指定時間**及之後**的資料 |
| `lt` | 小於 | 抓取指定時間**之前**的資料 |
| `lte` | 小於等於 | 抓取指定時間**及之前**的資料 |
| `eq` | 等於 | 抓取指定日期的資料 |

### 範例

```bash
# 抓取 2025/12/09 11:00:00 之後修改的資料
?where=1000834,gt,2025/12/09 11:00:00

# 抓取 2025/12/01 至 2025/12/31 之間的資料 (AND 邏輯)
?where=1000834,gte,2025/12/01&where=1000834,lte,2025/12/31

# 抓取今天的資料
?where=1000834,gte,2025/12/25&where=1000834,lt,2025/12/26
```

## 4. API 呼叫範例

### cURL 範例

```bash
# 設定環境變數
export RAGIC_API_KEY="your_api_key_here"

# 抓取訂單明細表在 2025/12/09 11:41:00 之後修改的資料
curl -H "Authorization: Basic $RAGIC_API_KEY" \
  "https://ap6.ragic.com/grefun/forms8/3?api&v=3&limit=1000&where=1000834,gt,2025/12/09%2011:41:00"

# 抓取客戶表在 2025/12/09 11:03:00 之後修改的資料
curl -H "Authorization: Basic $RAGIC_API_KEY" \
  "https://ap6.ragic.com/grefun/forms8/2?api&v=3&limit=1000&where=1000730,gt,2025/12/09%2011:03:00"
```

### URL 編碼注意事項

| 字元 | 編碼 | 說明 |
|------|------|------|
| 空格 | `%20` | 日期時間中的空格 |
| `:` | `%3A` | 時間中的冒號（通常不需編碼） |
| `/` | `%2F` | 日期中的斜線（通常不需編碼） |
| `,` | `%2C` | 值中包含逗號時需編碼 |

## 5. 增量抓取策略

### 建議流程

```
1. 讀取上次同步的時間戳記
   ↓
2. 使用 where 參數篩選該時間之後的資料
   ↓
3. 分頁抓取所有符合條件的資料
   ↓
4. 儲存資料並更新時間戳記
```

### 時間戳記管理

建議使用 JSON 檔案記錄各表的最後同步時間：

```json
{
  "10": "2025/12/25 14:30:00",
  "20": "2025/12/25 14:30:00",
  "99": "2025/12/25 14:30:00"
}
```

### 排序建議

增量抓取時建議按修改時間排序，確保資料順序一致：

```
order=1000834,ASC
```

## 6. 注意事項

### 1. 欄位 ID 必須正確

```bash
# ✅ 正確：使用欄位 ID
?where=1000834,gt,2025/12/09

# ❌ 錯誤：使用欄位名稱（不支援中文）
?where=最後修改日期,gt,2025/12/09
```

### 2. 日期格式必須正確

```bash
# ✅ 正確
?where=1000834,gt,2025/12/09 11:41:00

# ❌ 錯誤：使用 - 分隔
?where=1000834,gt,2025-12-09 11:41:00
```

### 3. 分頁處理

如果符合條件的資料超過 1000 筆，需要分頁處理：

```bash
# 第一頁
?limit=1000&offset=0&where=1000834,gt,2025/12/09

# 第二頁
?limit=1000&offset=1000&where=1000834,gt,2025/12/09
```

### 4. 處理刪除的資料

Ragic API 的 `where` 篩選只能抓取「修改或新增」的資料，無法偵測「刪除」的資料。

如需處理刪除的資料，建議：
- 定期進行全量同步（如每週一次）
- 或使用 Ragic Webhook 接收刪除事件
