### 2. 執行超時問題

**現象**：
- 增量備份 + 清洗總時間超過 540 秒 (9 分鐘) 限制
- 使用 `skip_cleaning: true` 也超時（300 秒 curl 超時）

**可能原因**：
1. 清洗邏輯沒有正確限制到增量資料
   - `SQLCleaner._fetch_records()` 使用 `cleaning_status IS NULL OR cleaning_status = 'pending'`
   - 這可能包含歷史所有未清洗的資料，而非只有當日增量

2. BigQuery 查詢效能問題
   - 每個 fill rule 執行獨立查詢
   - 可能需要批次優化

**待驗證**：
- [ ] 確認清洗邏輯是否正確過濾到增量資料
- [ ] 檢查 `cleaning_status IS NULL` 的記錄數量
